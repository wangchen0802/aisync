# AISync 产品设计文档 v0.1

> 一句话：**把团队散落在 ChatGPT / Claude / Cursor / Gemini 里的 AI 对话，自动提炼成大家都看得见的「决策、任务、结论」，再把这些团队共识喂回每个人的 AI。**

---

## 1. 问题定义

创业团队里，AI 已经成了每个人的"第二个同事"，但这个同事是**私有的**：

| 现象 | 后果 |
| --- | --- |
| 每个人用不同的 AI（ChatGPT、Claude、Cursor、Claude Code、Gemini、Perplexity…） | 信息被锁在 N 个工具 × M 个人的私人对话里 |
| 一个人一天开 5–20 个对话，大部分重要结论在对话里产生 | 决策在"暗处"发生，其他人不知道，也追溯不了 |
| 每次开新对话都要重新解释公司背景、产品、技术栈 | 重复喂上下文，浪费时间，且每个人喂的版本不一致 |
| A 和 B 同时让 AI 调研同一件事 | 重复劳动；更糟的是得出**互相矛盾**的结论却没人发现 |
| 站会/周报靠人工回忆 | 低效，漏掉大量 AI 辅助完成的工作 |

**核心洞察：**

1. **团队需要同步的不是对话本身，而是对话的产出。** 原始对话又长又乱，还包含隐私和试错；真正有价值的是其中的 *决策、任务、结论、未解决问题、产出物*。
2. **同步必须是双向的。** 只做"收集 → 展示"是一个看板，用了两周就没人看；把团队共识**反哺**回每个人正在用的 AI，才会形成日常依赖。
3. **默认私有，一键公开。** 没有人愿意被"监控聊天记录"。产品必须让个人先受益（自动日报、不用重复解释背景），分享是顺手的事。

## 2. 目标用户

- **首要用户：5–30 人的 AI-native 创业团队。** 创始人、工程师、产品、增长，每人日常使用 2+ 个 AI 工具。
- **角色与诉求：**
  - **创始人 / 负责人**："我想知道团队这周靠 AI 推进了什么、做了哪些决定，不想开会问。"
  - **工程师**："我在 Claude Code 里定了接口方案，希望前端同学的 Cursor 自动知道。"
  - **产品 / 运营**："我让 ChatGPT 做了竞品分析，别人又做了一遍，还结论不同。"

## 3. 产品原则

1. **产出优先于对话（Outcomes over transcripts）**：界面主角是卡片（决策 / 任务 / 洞察 / 问题），原始对话只作为可追溯的"来源"。
2. **零额外操作**：捕获自动完成，提炼自动完成，人只做一次"发布 / 保持私有"的判断。
3. **个人先受益**：即使不分享，用户也能得到自己的跨工具记忆和自动日报。
4. **随处可用**：不要求大家换 AI 工具，AISync 是嵌在现有工具旁边的一层。
5. **信任是产品本身**：可见性规则透明、敏感信息自动脱敏、管理员也看不到未发布的原始对话。

## 4. 核心闭环

```
   ┌──────────── ① 捕获 Capture ────────────┐
   │ 浏览器插件 / IDE & CLI 钩子 / 分享链接导入 │
   └───────────────────┬────────────────────┘
                       ▼
   ┌──────────── ② 提炼 Distill ────────────┐
   │ LLM 抽取：摘要 · 决策 · 任务 · 洞察 · 问题 │
   │ 自动识别项目、脱敏密钥与个人信息           │
   └───────────────────┬────────────────────┘
                       ▼
   ┌──────────── ③ 审核 Review（个人收件箱）─┐
   │ 一键：发布到团队 / 仅自己可见 / 丢弃       │
   └───────────────────┬────────────────────┘
                       ▼
   ┌──────────── ④ 同步 Sync ───────────────┐
   │ 团队动态流 · 决策日志 · 每日简报 · Slack  │
   │ 重复工作提醒 · 结论冲突检测               │
   └───────────────────┬────────────────────┘
                       ▼
   ┌──────────── ⑤ 反哺 Feed back ──────────┐
   │ MCP Server / 上下文包 → 每个人的 AI      │
   │ "我们上周对定价的决定是什么？"             │
   └──────────────────────────────────────┘
```

### ① 捕获（Capture）

| 渠道 | 覆盖工具 | MVP |
| --- | --- | --- |
| Chrome 插件 | ChatGPT、Claude.ai、Gemini、Perplexity 网页版 | ✅ |
| Claude Code / Cursor 钩子 + MCP | 会话结束时自动推送摘要 | ✅ |
| 分享链接 / 导出文件导入 | 各家官方 share link、JSON 导出 | ✅ |
| 手动粘贴 | 任意 | ✅ |
| 桌面端（原生 App 窗口） | ChatGPT / Claude 桌面版 | 后续 |
| API 代理 | 团队自建的 AI 应用 | 后续 |

- 插件只读取**用户自己当前页面**的对话，不抓取、不代登录。
- 用户可设置：全自动捕获 / 仅手动点"同步此对话" / 按站点白名单。

### ② 提炼（Distill）

对每个会话生成一个 **Session Summary**，并抽出若干 **Card**：

| 卡片类型 | 例子 | 说明 |
| --- | --- | --- |
| 🟦 决策 Decision | "MVP 用 Postgres + pgvector，不用独立向量库" | 带理由、备选方案、置信度 |
| 🟨 任务 Task | "Bob：周五前完成 Stripe webhook" | 可同步到 Linear / Jira |
| 🟩 洞察 Insight | "竞品 X 的定价是按席位 $12/月" | 带来源链接 |
| 🟪 问题 Question | "企业版是否需要 SSO？尚未定论" | 未决事项，可 @ 人 |
| ⬜ 产出物 Artifact | 一段代码、一份 PRD 草稿、一个 prompt | 可直接复用 |

- 自动归类到**项目**（基于团队已有的项目描述 + 语义匹配），可手动修正。
- **脱敏**：API Key、密码、手机号、邮箱、客户名单等自动打码，发布前高亮提示。

### ③ 审核（个人收件箱）

- 每个新会话进入**个人收件箱**，显示提炼结果。
- 三个动作：`发布到团队`、`仅自己可见`、`丢弃`；可以只发布部分卡片。
- 可设规则："Claude Code 里 `repo:aisync` 的会话自动发布" → 熟练后几乎零操作。

### ④ 同步（团队可见性）

- **团队动态流**：按项目 / 成员 / 卡片类型筛选，看"谁在用 AI 做什么"。
- **决策日志**：所有已发布决策按时间线排列，支持"被推翻/已替代"状态，形成团队的 ADR（架构决策记录）。
- **每日 / 每周简报**：自动生成，推送到 Slack / 飞书 / 邮件，替代异步站会。
- **重复工作提醒**：检测到你正在研究的主题与队友近 7 天的会话高度相似 → "Alice 昨天也调研了 Stripe vs Paddle，看看她的结论？"
- **冲突检测**：新决策与已有决策矛盾 → 标红并通知双方，一键发起讨论或标记取代关系。

### ⑤ 反哺（让每个 AI 都知道团队共识）

这是留存的关键。

- **AISync MCP Server**：在 Claude Desktop / Claude Code / Cursor 等支持 MCP 的工具里安装，AI 可以调用：
  - `search_team_memory(query)` — "我们对定价做过什么决定？"
  - `get_project_context(project)` — 拉取项目背景、技术栈、最近决策
  - `log_decision(...)` / `create_task(...)` — 在对话中直接写回
- **上下文包（Context Pack）**：为每个项目自动维护一份精简背景文档（≤2k tokens），可一键复制到 ChatGPT 自定义指令 / Claude Project 知识库 / `CLAUDE.md`。
- **插件侧边栏**：在 ChatGPT / Claude 网页开新对话时，侧边栏推荐"相关团队记忆"，点击即插入。

## 5. 信息架构

```
Workspace（团队）
├── 团队动态 Feed          ← 默认首页
├── 收件箱 Inbox           ← 我的待审核会话
├── 项目 Projects
│   ├── 概览：上下文包 · 活跃成员 · 未决问题
│   ├── 决策日志
│   ├── 任务
│   └── 会话
├── 团队记忆 Memory         ← 全局搜索 + 问答
├── 简报 Digest
└── 设置：成员 · 集成 · 捕获规则 · 隐私
```

## 6. 关键页面

1. **团队动态**：三栏布局 —— 左侧项目/成员导航，中间卡片流，右侧"需要你关注"（冲突、@你的问题、重复提醒）。
2. **收件箱**：左侧会话列表（显示来源工具图标），右侧提炼结果预览 + 脱敏高亮 + 发布按钮。
3. **项目页**：顶部是可复制的上下文包，下方为决策时间线和未决问题。
4. **团队记忆**：一个搜索框，支持自然语言提问，回答附带来源卡片与原始会话链接。
5. **简报**：按人 / 按项目两种视图，今日要点 + 新决策 + 阻塞。

可交互原型见 [`prototype/index.html`](../prototype/index.html)。

## 7. 数据模型（MVP）

```
Workspace(id, name)
Member(id, workspace_id, name, role)
Project(id, workspace_id, name, description, context_pack)
Session(id, member_id, source[chatgpt|claude|cursor|claude_code|gemini|...],
        source_url, started_at, raw_ref(加密存储), summary,
        visibility[private|team], project_id)
Card(id, session_id, project_id, type[decision|task|insight|question|artifact],
     title, body, owner_id, status, visibility, embedding,
     supersedes_card_id)
Link(card_a, card_b, relation[duplicate|conflict|related|supersedes])
Digest(id, workspace_id, period, content, sent_at)
```

- 原始对话**加密存储**，仅作者可见；团队只能看到发布的卡片与摘要。
- 所有卡片带 embedding，用于检索、重复检测与冲突检测。

## 8. 隐私与权限

| 对象 | 作者 | 团队成员 | 管理员 |
| --- | --- | --- | --- |
| 原始对话 | ✅ | ❌（除非作者分享） | ❌ |
| 私有卡片 | ✅ | ❌ | ❌ |
| 已发布卡片 / 摘要 | ✅ | ✅ | ✅ |
| 使用统计（数量级，不含内容） | ✅ | ❌ | ✅ |

- 脱敏在**客户端插件**先做一轮，服务端再做一轮。
- 支持自带 LLM Key / 私有部署（后续企业版）。
- 明确告知：AISync **不是**监控工具，不提供"员工 AI 使用排行"之类功能。

## 9. MVP 范围（6 周）

**必须有**
- Chrome 插件：ChatGPT + Claude.ai 捕获
- Claude Code 钩子（SessionEnd 推送摘要）
- 提炼流水线：摘要 + 4 种卡片 + 项目归类 + 脱敏
- 收件箱审核 + 团队动态流
- 每日简报推送到 Slack
- MCP Server（只读：`search_team_memory`、`get_project_context`）

**暂不做**
- 原始对话全文的团队搜索
- 任务管理本身（只同步到 Linear/Jira）
- 移动端 App
- 企业 SSO、私有部署

**里程碑**

| 周 | 交付 |
| --- | --- |
| 1–2 | 插件捕获 + 数据模型 + 提炼 v0（自己团队内测） |
| 3 | 收件箱 + 动态流 |
| 4 | MCP Server + 上下文包 |
| 5 | Slack 简报 + 重复/冲突检测 v0 |
| 6 | 5 个设计伙伴团队试用 |

## 10. 成功指标

- **北极星指标：每周"上下文复用"次数** —— 一个人的卡片被他人查看、引用，或被他人的 AI 通过 MCP 调取。
- **激活**：新成员首周捕获 ≥5 个会话且发布 ≥3 张卡片。
- **留存**：团队 W4 周活成员占比 ≥60%。
- **价值信号**：简报打开率；冲突/重复提醒的点击率；"站会时长下降"的定性反馈。

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 员工抵触"被看聊天记录" | 默认私有、原始对话永不对外、先给个人价值（自动日报/个人记忆） |
| AI 厂商页面结构变化导致插件失效 | 选择器配置化远程下发；同时支持官方导出/分享链接兜底 |
| 提炼质量不稳定（漏掉或编造决策） | 卡片必须附原文引用片段；用户纠错数据用于迭代 prompt |
| 厂商自己做团队功能（ChatGPT Team、Claude Team） | 我们的价值在**跨厂商**+**跨角色**，单一厂商天然做不到 |
| 信息过载，又变成没人看的看板 | 只推"需要你关注"的内容；简报限长；反哺通道让信息在用的时候出现 |

## 12. 竞品与差异化

| 类别 | 代表 | 我们的差异 |
| --- | --- | --- |
| 单厂商团队版 | ChatGPT Team/Enterprise、Claude Team | 只覆盖自家对话 |
| 企业知识搜索 | Glean、Notion AI | 索引文档，不理解 AI 对话里的决策 |
| 个人 AI 记忆 | Mem、各类对话导出插件 | 个人工具，没有团队同步与冲突检测 |
| 开发者上下文 | Cursor rules、CLAUDE.md | 手工维护、单仓库、只覆盖工程师 |

**定位：跨 AI 工具的团队共识层（Team Context Layer for AI）。**

## 13. 待验证的假设（建议先做用户访谈）

1. 团队成员愿意在 1 周内把 ≥50% 的 AI 会话交给 AISync 捕获？
2. "反哺到 AI"是否比"团队看板"更能驱动留存？
3. 决策冲突检测的真实发生频率是否足够高，值得作为核心卖点？
4. 付费方：创始人还是工程负责人？按席位还是按团队？

建议访谈问题：
- 上周你用 AI 做出的最重要的一个决定是什么？团队其他人知道吗？怎么知道的？
- 你最近一次向 AI 重复解释公司背景是什么时候？花了多久？
- 有没有发现过和同事让 AI 做了同一件事？
