# SimReal Sync 产品设计 v0.3

> **一句话**：团队每个人在各个 AI 里的对话，自动沉淀成团队的**共识、任务、目标和记忆**；任何人的任何 AI，在开口之前都先读到这份团队记忆。

v0.3 相对 v0.2 的变化：从「对话聚合」升级为「团队记忆 + 轻量团队管理」。新增本周目标、DDL、个人想法、四层上下文与上下文引擎、Lark 集成。

---

## 1. 设计原则

1. **少对象**：全产品只有 4 个核心对象（共识、任务、目标、想法），所有页面都是这 4 个对象的不同视图。
2. **记录零成本**：AI 自动提炼、按 C 快速记录、同步后自动发布。人只做判断，不做搬运。
3. **AI 先读再说**：团队记忆的首要读者是 AI，其次才是人。每一条记录都有编号，方便 AI 引用、人核对。
4. **默认私有，主动公开**：原始对话只有作者本人可见；想法默认仅自己可见；敏感内容自动打码并留在收件箱。
5. **在 Lark 里闭环**：提醒、确认请求、周报都推送到 Lark，点一下回到对应页面。

## 2. 核心对象

| 对象 | 编号 | 状态 | 来源 | 关键字段 |
| --- | --- | --- | --- | --- |
| **共识** Decision | D-12 | 讨论中 → 已确认 / 有冲突 / 已推翻 | AI 提炼、快速记录、MCP `log_decision` | 理由、备选方案、原文片段、确认人 |
| **任务** Task | T-34 | 待开始 / 进行中 / 阻塞 / 已完成 | 同上 + MCP `create_task` | 负责人、**DDL（日期）**、子任务、依赖决策、关联目标 |
| **目标** Goal | — | 正常推进 / 有风险 / 已达成 / 未达成 | 手动（每周） | 团队或个人、所属周、项目、进度（由关联任务自动计算） |
| **想法** Idea | N-7 | 仅自己 → 已分享 → 已转化 | 快速记录、想法页 | 默认私有；一键分享或转成共识/任务/问题 |

辅助对象：待定问题（Q）、洞察（I）、讨论（评论）、对话存档（原始文本）。

**对象之间的关系**：目标 ← 任务（`goal_id`）；任务 → 依赖的共识（`blocked_by`，共识确认后自动解除阻塞）；想法 → 转化出的共识/任务；新共识 ↔ 冲突的旧共识。

## 3. 上下文怎么保存：四层记忆

```
┌──────────────────────────────┐
│ ① 团队档案   手写，很少变     │  我们是谁、阶段、技术栈、术语、工作方式
├──────────────────────────────┤
│ ② 项目背景   手写，按项目     │  目标、范围、约束、链接
├──────────────────────────────┤
│ ③ 实时状态   自动生成         │  本周目标 · 共识 · 讨论中 · 任务与 DDL · 待定问题 · 洞察 · （我的想法）
├──────────────────────────────┤
│ ④ 对话存档   仅作者可见       │  原始对话，只用于提炼和追溯，不直接给 AI
└──────────────────────────────┘
```

- **①② 由人维护**，是 AI 最缺的「长期背景」。放在「记忆」页，带模板和 token 计数。
- **③ 永远是实时的**：不存快照，每次读取都从数据库生成，所以不会过期。
- **④ 不进上下文**：原始对话很长、很乱、有隐私，只保留提炼结果。需要追溯时从条目的「原文片段」跳回去。

## 4. 核心：AI 怎么读取

### 4.1 上下文引擎（`buildContext`）

输入：范围（团队 / 项目 / 我的）、可选话题、长度预算（2k / 6k / 12k tokens）。

按固定优先级拼装，超出预算就截断，并告诉 AI「另有 N 条，可用 `search_team_memory` 查询」：

1. 团队档案
2. 项目背景（范围是项目时）
3. 本周目标（含进度）
4. **与当前话题相关的条目**（有话题时，检索排序后放在最前）
5. 已确认的共识（必须遵循）
6. 讨论中 / 有冲突的决策（未定论）
7. 进行中的任务（按 DDL 排序，带负责人、进度、最新进展）
8. 待定问题
9. 近期洞察
10. 我的想法（仅「我的」范围）
11. 给 AI 的规则：遵循共识、冲突时指出编号、对话末尾列出新决策/任务/DDL

每一行都是统一格式：`[D-12] (已确认) 结论 —— 理由 · 负责人 · 项目 · DDL 2026-09-26（周五） · 最新：…`

### 4.2 五种读取方式

| 方式 | 适用 | 特点 |
| --- | --- | --- |
| **MCP**（Resources + Tools） | Claude Code、Cursor、Claude Desktop | AI 主动读取和查询：`get_team_context(topic)`、`get_my_work`、`search_team_memory`；并能写回：`log_decision`、`create_task`、`update_task`、`sync_conversation` |
| **浏览器插件** | ChatGPT、Claude、DeepSeek、Gemini、Grok 网页版 | 「插入团队上下文」把当前对话标题作为话题，相关内容排在最前 |
| **只读链接** `/c/<key>` | 能联网的 AI | 「先读这个链接再回答」；只读、可重置，支持 `scope` / `topic` / `project` |
| **.md 文件** | ChatGPT / Claude 的 Project 知识库 | 下载即上传 |
| **复制** | 任何 AI | 粘贴到对话开头 |

### 4.3 写回闭环

对话 → 插件 / Hook / MCP → 提炼（Claude 结构化输出，带「今天是几号」以换算 DDL；已同步过的对话只处理新增内容，并把已有结论传给模型避免重复）→ 收件箱或自动发布 → 冲突 / 重复检测 → 通知 → 下一次读取时已包含。

## 5. 团队管理

- **本周**（`/week`）：团队目标 + 我的目标（进度由关联任务的子任务自动计算，没有关联任务时可手动拖动）；本周 DDL 日历；每天完成的任务图；本周回顾（一键发到 Lark 群）；延续上周未完成目标。
- **任务**（`/tasks`）三种视图：
  - **看板**：拖动或点「开始 / 完成」推进。
  - **时间线**：按项目分组的甘特图，创建 → DDL 区间，子任务完成度填充，逾期红色延长，今天竖线，悬停看详情。
  - **按人**：每人未完成 / 7 天内到期 / 逾期 / 已完成，状态分布条，最近 5 个任务。
- **DDL**：真正的日期字段。支持「周五前」「下周三」「9月30日」等说法自动换算；颜色区分逾期 / 今天 / 两天内 / 以后。

## 10. 融资与外联

创业公司最要紧、也最容易散在各自邮箱和微信里的，是和投资人、客户、候选人的沟通。这一块按「管道」来管：

| 管道 | 阶段 |
| --- | --- |
| 融资 | 待联系 → 已联系 → 已见面 → 尽调 → 谈条款 → 已承诺 → 已到账（/ 放弃） |
| 客户 | 待联系 → 已联系 → 已回复 → 演示 / 试用 → 谈合同 → 成交（/ 未成） |
| 合作 | 待联系 → 已联系 → 已回复 → 已沟通 → 推进中 → 达成合作（/ 未成） |
| 招聘 | 待联系 → 已联系 → 有意向 → 面试中 → 谈 offer → 已入职（/ 未成） |

- **本轮进度**：目标金额、已到账、已承诺、谈条款中的金额叠在一条进度条上；加权管道 = 每个投资人的预期金额 × 所处阶段的成功概率；漏斗显示每一步的转化。
- **一个联系人一页**：阶段条（点一下就改阶段）、记录跟进（邮件 / 会议 / 电话 / 消息 / 备注 + 下一步 + 跟进日期，常用日期一键选）、完整的沟通时间线、资料。
- **不让人掉线**：跟进日期 2 天内到期，或推进中却 14 天没联系，会出现在「要跟进」、总览的待处理、侧栏计数和 Lark 早间私信里。
- **进来和出去**：从表格直接粘贴或选 CSV 导入（自动识别表头、按邮箱去重），导出 CSV（Excel 可直接打开）。
- **AI**：根据沟通记录和团队档案起草跟进邮件（中文 / English）；MCP 的 `log_outreach` 让你在 Claude / Cursor 里一句话记下会议，`get_pipeline` 让 AI 写投资人更新前先读管道。
- **权限**：融资管道可以设为仅管理员可见，页面、搜索、导出、MCP 都按这个设置过滤。融资数据不进入发给 AI 的团队上下文。

## 11. 刻意不做

- 不做完整项目管理（Sprint、工时、甘特依赖线）——Lark / Linear 已经很好，我们只做「AI 对话产生的工作」。
- 不做原始对话全文共享——隐私是这个产品能被用起来的前提。
- 不做员工 AI 使用排行——只统计次数，不做监控。
